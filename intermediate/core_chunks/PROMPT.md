# 任务：为四级高频多义小词写「核心意象」

## 背景

这是一份四级高频词背诵表。像 take / get / over 这样的短小常用词，词典会列一串看似毫不相干的中文义项（拿；采取；花费；乘坐），学生只能死记。「核心意象」用**一个具体画面**把这些义项串起来，再用一行推导说明每个义项是怎么从画面里长出来的。

长的大词（有词根拆解的）不在本任务范围，已经排除。

## 样板（风格以它为准）

`intermediate/core_manual.json` 里已人工写好 16 条（take get make have put hold keep set turn run over into out up break carry）。**动笔前先读它**，措辞长度、标点、推导写法都照它来。例：

```json
"take": {"image": "主动伸手，把外面的东西拿到自己这边",
         "derive": "拿；取 ⇒ 采取（把办法拿来用）；乘坐（把车拿来用）；服用（把药拿进身体）；花费（事情把你的时间拿走：It takes two hours）"}
```

## 输入

`intermediate/core_chunks/in_XX.json`：`[{rank, word, def}]`。`def` 是表里给学生看的中文释义，你的卡片要解释的就是这些义项。

`intermediate/core_chunks/all_words.txt`：全部 1250 词（rank、word、是否有词根），用来判断变形词的原形在不在表里。

## 输出

`intermediate/core_chunks/out_XX.json`（XX 与输入相同），一个 JSON 对象，**输入里的每个词都必须作为键出现**，值是以下三种之一：

1. **卡片** `{"image": "...", "derive": "..."}`
2. **复用原形** `{"same_as": "take"}` —— 词是表中另一个词的屈折变形（takes / taking / took / getting / studies / found…），且它的 `def` 没有原形之外的独立义项，**且原形在 all_words.txt 里**。原形不在表里时，就按原形的意思直接写卡片（或 null）。
3. **不做** `null`

## 什么时候写卡片（准确优先于覆盖）

写卡片，必须**同时**满足：
- `def` 里有 2 个以上**学生看来不相干**的义项（"帮助; 援助; 改善" 这种近义堆叠不算；"学生" 这种单义不算）；
- 确实存在一个**真实的**核心意义把它们串起来——以英文母语者语感、Longman/Collins/Oxford 的义项结构或可靠词源为准。

一律给 `null` 的情况：
- 纯语法功能的词（the, a, is, are, can, will 的情态用法、代词 it/they/which…）；但 **介词/副词小品词**（through, by, for, on, at, off, down, back…）常常有清晰的空间画面，是重点对象，认真做；
- 义项都很接近、一看就懂的词；
- 要靠牵强附会、民间词源才能串起来的词。**宁可 null，不要编**。

## 写法规则

- `image`：一个**具体的动作或空间画面**，不是词典释义的翻版。一般 8–20 个汉字。
- `derive`：
  - 先写最贴近画面的基本义，接 ` ⇒ `，再逐个写引申义，每个义项后用全角括号写一句**为什么**（画面怎么变成这个意思），可附很短的英文搭配（`：run a business`）。
  - 义项之间用全角分号「；」。只用 `def` 里出现的义项，不额外添义项。
  - 词性切换时标出（`n. 轮到（…）`、`adj. 固定的（…）`）。
  - 有义项确实与画面无关（同形异源、或语义早已断开）时，放在最后写「X 单独记」，如 `n. 一套另有来源，单独记`。不要硬扯。
  - 一般不超过 110 个汉字。
- 全部中文标点；英文搭配用半角。不要 Markdown、不要换行。

## 交付前自检

用 Python 校验：文件是合法 JSON；键集合与输入的 word 集合完全相同；卡片的 image、derive 都非空；same_as 的目标在 all_words.txt 里。最后报告：卡片数 / same_as 数 / null 数，并列出你**最拿不准**的 3–5 条及原因。
